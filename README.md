# Aphendo

단체메일 공문이나 화면 일부를 캡처하면 원격 MCP 서버(`extract_todos`)가 할일을 뽑아 달력의 마감일 칸에 올려 줍니다. 처음 화면은 월간이고 위쪽에서 주간(월~금 5열)으로 바꿉니다. 왼쪽에는 작은 달력, 오늘 할 일, 기한 초과가 있고, 아래 버튼으로 마감 없음·전체 할 일·완료·통화 메모 목록을 엽니다.

할일 제목에 마우스를 올리면(또는 Tab 으로 옮기면) 근거 캡처와 추출 내용이 뜨고, 누르면 상세 창이 열립니다. 캡처 이미지는 위쪽 **캡처 목록**에서 봅니다. 이미 있는 할일과 비슷한 할일이 들어오면 바로 추가하지 않고 **중복 확인** 창에서 기존 유지, 근거 추가, 별도 추가 중 고르게 합니다. 테마(블랙, 화이트, 블랙 & 화이트, 파스텔, 추천)와 색은 ⚙ 설정에서 바꿉니다.

## Windows 설치

1. [최신 릴리즈](https://github.com/team-poem/aphendo/releases/latest)에서 `Aphendo_<버전>_x64-setup.exe` 를 받아 실행합니다. 예전 이름인 CaptureTodo 가 깔려 있으면 먼저 제거합니다. 데이터는 그대로 남습니다. 서명하지 않은 설치 파일이라 SmartScreen 경고가 뜨면 **추가 정보 → 실행**을 누릅니다. WebView2 가 없으면 설치 중에 내려받습니다.
2. 처음 실행하면 **설정** 창이 뜹니다. 나중에는 제목 줄의 ⚙ 로 엽니다.
3. 받은 접속 토큰을 붙여 넣고 **연결 확인**을 누릅니다. "연결됨"이 보이면 **저장**합니다. "401"이면 토큰이 틀린 것이고, "서버에 연결할 수 없습니다"면 네트워크 문제입니다.
4. **Alt+Shift+S** 로 화면 일부를 캡처하면 할일이 달력에 올라옵니다.

## 화면 캡처 (데스크톱 앱)

1. **Alt+Shift+S** 를 누르거나 달력 위의 **캡처** 버튼을 누릅니다. (Win+Shift+S 는 Windows 캡처 도구가 쓰므로 피했습니다.)
2. 위젯이 잠깐 숨고 마우스가 있는 모니터 화면이 멈춘 채로 어둡게 깔립니다.
3. 끌어서 영역을 고르면(크기가 픽셀로 표시됨) 오른쪽 아래 **완료**(또는 Enter)를 눌러야 저장되고 분석이 시작됩니다. 다시 끌면 새로 고르고, 위쪽 **✕ 캡처 취소**나 Esc로 닫습니다. 모든 모니터에서 고를 수 있습니다.
4. Esc, 우클릭, 8px보다 작은 드래그는 취소입니다.

마우스가 있는 모니터 하나만 캡처합니다. 다른 도구로 캡처한 이미지는 위젯에 Ctrl+V 하거나 파일을 끌어다 놓으면 됩니다.

macOS 에서 개발할 때는 **시스템 설정 → 개인정보 보호 및 보안 → 화면 기록**에서 앱을 실행한 터미널을 허용해야 합니다. 허용하지 않으면 캡처가 실패하거나 배경화면만 찍힙니다.

## 설정

MCP 서버 주소는 코드(`core/src/remote.rs` 의 `MCP_URL`)에 고정돼 있고 화면에 나오지 않습니다. 사용자는 ⚙ 설정에서 접속 토큰만 넣으며, 토큰은 `config.json` 에 저장만 되고 다시 표시되지 않습니다. 개발할 때는 환경변수 `MCP_URL` 로 주소를, `MCP_TOKEN` 으로 토큰을 바꿀 수 있습니다(`config.json` 의 토큰이 우선). 캡처마다 다시 읽으므로 앱을 재시작하지 않아도 됩니다. 데이터 폴더는 `CAPTURE_TODO_DATA` 로 바꿀 수 있고, 기본값은 Windows `%APPDATA%\capture-todo`, macOS `~/Library/Application Support/capture-todo` 입니다. 캡처 이미지(`images/`)와 `store.json` 이 여기에 저장됩니다.

## 휴지통과 복구

할 일(직접 입력·캡처 등록), 통화 메모, 캡처를 삭제하면 바로 지워지지 않고 **휴지통**으로 이동합니다. 삭제 안내의 **되돌리기**로 취소하거나 왼쪽 메뉴의 **휴지통**에서 검색·종류 필터·다중 선택 후 복구할 수 있습니다. 보관 기한과 자동 영구 삭제는 적용하지 않습니다.

복구는 같은 ID의 원본을 되살리며 날짜·중요도·완료 상태·비고·완료 코멘트·근거 연결을 유지합니다. 지난 마감일도 그대로 유지합니다. 할 일 상세의 **삭제·복구 이력**에 시각과 ‘이 기기 사용자’를 표시합니다. 삭제한 업무는 일반 목록·캘린더·통계·주간업무 초안의 자료에서 제외되며, 이미 저장한 주간업무 문서는 수정하지 않습니다.

캡처만 휴지통으로 옮겨도 연결된 업무는 유지되며 해당 업무에서 근거를 계속 볼 수 있습니다. **영구 삭제**와 **휴지통 비우기**는 대상을 확인한 뒤 실행합니다. 다른 업무(휴지통의 업무 포함)나 중복 확인 항목이 쓰는 캡처가 포함되면 선택 전체의 영구 삭제를 거절합니다. 업무를 영구 삭제해도 캡처와 독립된 후속 업무는 함께 지우지 않습니다. 상위 업무를 영구 삭제한 후 후속 업무를 복구하면 연결 없이 일반 할 일로 돌아옵니다. 이미지 파일 정리에 실패하면 오류를 표시하고, 이미 확정한 파일 삭제만 다음 영구 삭제 작업 또는 재시작 때 재시도합니다.

현재 데이터 구조에는 프로젝트·단계·독립 댓글·세부 업무·예약 알림이 없습니다. 해당 기능을 도입할 때 휴지통과 연결해야 합니다. 이번 기능은 업무에 포함된 비고·완료 코멘트를 업무와 함께 보관하며, 없는 댓글·프로젝트 기능이나 알림 발송을 새로 만들지 않습니다. 기존 `store.json`은 새 필드가 없어도 읽을 수 있습니다.

## 웹 테스트 모드

같은 앱을 브라우저에서 띄웁니다.

```sh
pnpm install
pnpm build                                   # ui/dist 생성
cargo run -p core --example fake_mcp         # 선택: 가짜 MCP 서버 (127.0.0.1:8787, 토큰 devtoken)
MCP_URL=http://127.0.0.1:8787/mcp MCP_TOKEN=devtoken cargo run -p core --bin web
```

http://127.0.0.1:47321 을 열고 이미지를 붙여 넣습니다. 웹 모드에는 단축키와 캡처 버튼이 없고 붙여넣기·끌어다 놓기만 됩니다. UI를 고치면서 보려면 `pnpm dev` 로 http://localhost:5173 을 엽니다(`/api` 는 47321로 프록시).

## 아이콘과 테마

앱·설치 파일·브라우저 아이콘과 할 일 완료 마크는 `ui/src/brand-geometry.ts`의 같은 벡터 모양을 사용합니다. 모양이나 브랜드 색상을 바꾼 뒤 `pnpm icons`를 실행하면 투명 SVG와 데스크톱용 PNG/ICO/ICNS가 함께 갱신됩니다. Node.js 22.18 이상이 필요합니다.

설정의 **아펜도 라이트 / 아펜도 다크**는 보라색과 세이지 라임의 채도를 낮춘 테마입니다. 테마 팔레트와 완료 마크 색상은 `ui/src/theme.ts`에서 관리하며 기존 사용자 지정 색상은 유지합니다.

## Windows 개발·빌드

Rust, Node.js, pnpm, [Tauri 2 사전 요구사항](https://v2.tauri.app/start/prerequisites/)(WebView2, MSVC 빌드 도구)이 필요합니다.

```powershell
pnpm install
$env:MCP_URL="https://…/mcp"; $env:MCP_TOKEN="…"
pnpm tauri dev      # 개발 실행
pnpm tauri build    # 설치 파일: target\release\bundle\
pnpm test           # 캡처 영역 좌표 계산 테스트
```

### macOS 에서 Windows 설치 파일 만들기

[Tauri 문서의 교차 컴파일](https://v2.tauri.app/distribute/windows-installer/#build-windows-apps-on-linux-and-macos) 방식입니다. 토큰은 빌드에 넣지 않습니다.

```sh
rustup target add x86_64-pc-windows-msvc
cargo install --locked cargo-xwin
brew install nsis llvm
PATH="/opt/homebrew/opt/llvm/bin:$PATH" \
pnpm tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis
# → target/x86_64-pc-windows-msvc/release/bundle/nsis/Aphendo_<버전>_x64-setup.exe
```

### 릴리즈와 자동 업데이트

설치된 앱은 켜질 때와 30분마다 `releases/latest/download/latest.json` 을 확인합니다. 새 버전이 있으면 제목 줄에 **업데이트** 버튼이 뜨고, 누르면 받아서 서명을 확인한 뒤 설치하고 다시 시작합니다.

`src-tauri/tauri.conf.json`의 버전을 올리고 같은 버전의 태그를 푸시한 뒤, 해당 태그를 지정해 원격 빌드를 시작합니다.

```sh
gh workflow run release.yml --ref main -f tag=v0.2.18
```

Windows 실행기 배정이 오래 걸리면 Linux에서 Windows 설치 파일을 교차 빌드할 수 있습니다.

```sh
gh workflow run release.yml --ref main -f tag=v0.2.18 -f runner=ubuntu-24.04
```

워크플로는 지정한 태그의 소스를 확인한 뒤 테스트하고, 기존 키로 서명된 Windows 설치 파일과 `latest.json`을 포함한 초안 릴리즈를 만듭니다. GitHub에서 설치 파일과 업데이트 정보를 확인한 뒤 초안을 게시합니다. 태그와 앱 버전이 다르거나 서명 검증에 실패하면 업로드 전에 중단됩니다. 아래 검증 스크립트가 포함된 태그부터 실행할 수 있습니다. 기존 로컬 릴리즈 스크립트와 동시에 배포하지 않도록 태그 푸시만으로는 워크플로가 자동 실행되지 않습니다.

**v0.2.17부터 사용 중인 서명 키를 계속 유지합니다.** 키가 없거나 맞지 않으면 기존 백업을 복구하며, 일반 릴리즈를 위해 새 키를 발급하거나 공개키를 교체하지 않습니다. v0.2.16 이하 사용자는 v0.2.17을 한 번 직접 설치해야 하지만, 이후 버전에는 같은 키를 사용합니다.

- GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY`: 현재 비밀키. 암호가 있는 키는 secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`도 설정합니다.
- GitHub Actions variable `TAURI_SIGNING_PUBLIC_KEY`: v0.2.17에서 사용하는 공개키. 저장소의 `scripts/updater-public-key.pub`와 동일하게 유지합니다.
- 로컬 비밀키: `~/.tauri/aphendo.key` 또는 `APHENDO_SIGNING_KEY`로 지정한 파일. Git이나 릴리즈에 올리지 않습니다.

`scripts/release-signing.mjs preflight`는 앱 공개키가 고정된 키와 같은지 확인하고, 비밀키로 임시 데이터를 서명한 뒤 공개키로 검증합니다. 빌드 후에는 실제 설치 파일의 서명과 서명된 버전을 검증한 경우에만 `latest.json`을 만들고 업로드합니다. 비어 있는 키, 다른 키, 변조된 파일, 버전 불일치는 모두 배포를 중단시킵니다.

GitHub secret은 설정 후 원문을 다시 내려받을 수 없으므로 **원본 비밀키의 암호화된 별도 백업**을 릴리즈 담당자가 보관해야 합니다. 컴퓨터를 바꿀 때는 새 키를 만들지 말고 기존 키를 복구한 뒤 다음 검사를 통과시킵니다. 일반 앱 사용자에게 비밀키를 전달하지 않습니다.

```sh
node scripts/release-signing.mjs preflight
pnpm test:release
```

macOS에서 직접 빌드하고 게시하는 기존 스크립트도 사용할 수 있습니다.

```sh
scripts/release.sh 0.2.18 "바뀐 점 한 줄"
```

이 스크립트도 기존 키 검증 후 버전을 올려 빌드하고, 설치 파일 서명 검증을 통과한 경우에만 커밋과 태그를 푸시한 뒤 릴리즈를 게시합니다. 키 분실 자체를 검증 절차로 복구할 수는 없으므로 백업을 유지해야 합니다.

## 동작 메모

- 분석은 30~180초 걸리며 240초가 지나면 실패로 표시됩니다. 실패 칩을 누르면 재시도합니다.
- 같은 캡처를 재시도해도 제목이 같은 할일은 중복으로 추가되지 않습니다. 다른 캡처끼리는 중복을 거르지 않습니다.
- 앱이 분석 도중 종료되면 다음 실행 때 그 캡처는 "앱 재시작으로 중단" 실패로 바뀌고 재시도할 수 있습니다.
- 창은 테두리 없음이고 기본 1100×760, 최소 400×520 으로 크기를 바꿀 수 있습니다. 제목 줄(넓을 때는 오른쪽 패널 위, 좁을 때는 맨 위)을 끌어 옮기고 − 로 최소화, × 로 종료합니다.
